# Harness 工程六支柱

> 让一个只会说话的语言模型，变成一个能可靠完成复杂任务的执行者。每个核心解决一类"光靠聪明不够"的问题。

## 01 上下文管理 — 模型看到了什么

每次对话，模型能"看到"的信息是有限的。上下文管理就是决定喂给模型什么、截断什么、压缩什么。你有没有注意到长对话到后面，我会说"之前的内容已被压缩"？这就是上下文管理在工作——把早期对话总结成摘要塞回去，保证我不丢失关键信息，同时不超出上下文窗口。

类比：人的工作记忆，桌面能放多少文件。

## 02 工具系统 — 模型能做什么

模型本身只会说话。工具系统给它装上了"手"——读文件、写文件、跑命令、搜网页、操作浏览器。你用到的 python-docx 生成 Word、yt-dlp 下载音频、CDP 操作 Chrome，都是工具系统的能力边界。工具定义了模型能触达什么、不能触达什么。

类比：给一个聪明的实习生配了电脑、打印机、电话，他才能干活。

## 03 执行编排 — 模型下一步该做什么

一个复杂任务拆成多步，先做什么后做什么、什么时候该并行、什么时候该等上一步完成。比如刚才生成 Word 文档的流程：恢复用户内容 → 写脚本 → 验证引号 → 运行 → 再验证——每一步的顺序和判断就是执行编排。

类比：项目经理排任务、定优先级、控节奏。

## 04 状态与记忆 — 跨步骤保持连续性

对话中间断了、上下文被压缩了，系统怎么"记住"之前在干什么。你现在用的 MEMORY.md 文件、每次启动读 CLAUDE.md，就是记忆系统。没有这个，每次新对话我就是一张白纸，不知道你是谁、你的工作是什么、你上次纠正过我什么。

类比：笔记本 + 档案柜，不只是脑子里的记忆。

## 05 评估与观测 — 怎么知道自己做得对不对

模型生成了内容，但怎么验证？刚才生成 Word 后我跑了一段 Python 去检查有没有 {LQ} 残留、段落数量对不对——这就是评估。观测是指整个过程中，你能看到我在做什么、中间结果是什么，而不是黑箱运行。

类比：质检环节 + 过程透明化。

## 06 约束与恢复 — 出错了怎么办、怎么防跑偏

CLAUDE.md 里的防御性规则（不自动修改 CLAUDE.md、删文件前要确认、操作前 dry-run）就是约束。恢复是出了问题怎么回退——比如刚才引号修了还有问题，我就扫描全部 f-string 重新定位。核心思路：预防为主（约束），出错能兜底（恢复）。

类比：安全带 + 安全气囊——最好不用，但必须有。

## 用途：Agent / Skill 评估框架

用这六支柱作为评估清单，逐项检查任何 agent 系统或 skill：

| 支柱 | 评估问题 | 评分 |
|------|---------|------|
| 01 上下文管理 | 是否有明确的上下文加载/截断策略？是否避免全量读入？ | 0-5 |
| 02 工具系统 | 是否使用目标平台原生工具？工具映射是否明确？ | 0-5 |
| 03 执行编排 | 流程是否分阶段？每阶段是否有完成判定？是否支持并行/串行切换？ | 0-5 |
| 04 状态与记忆 | 是否有跨会话记忆？记忆是否分层？是否与平台记忆系统兼容？ | 0-5 |
| 05 评估与观测 | 是否有输出验证机制？是否可追踪中间状态？是否有评分体系？ | 0-5 |
| 06 约束与恢复 | 是否有安全约束？是否只追加不覆盖？是否有回退机制？ | 0-5 |

**总分 0-30**，解读：
- 24-30：生产就绪
- 18-23：可用，有改进空间
- 12-17：需要补强
- 0-11：设计不足，需重新评估
